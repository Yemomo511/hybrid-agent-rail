## Docs
文档系统，主要存储开发过程中的架构决策，使用说明等。文档作为系统管理，每个文档应该保持一致的结构，文档需要被系统化处理，需要被治理，被管理，被纠正，及时更新，防止漂移。

## Ignore
- skills 和 agents 单个Skill的说明不需要记录文档，只需要记录整个Skill 模块和 Agents 模块。

## Written Rules
哪些内容应该进入文档系统
1. 稳定约定：包括 Agent / Skill 职责边界、模块文档结构架构、文件系统结构、命名规范、输入输出契约、产物格式、门禁规则和权威来源路径。凡是会影响未来 Agent 如何判断、调用、编排、恢复的内容。
2. 决策依据：当存在多种实现路径时，需要记录最终选择、取舍原因、适用边界和被否定的错误路径，并给出一个最终的实现路径结论，防止后续 Agent 因上下文缺失重复走错方向。
3. 模块接口和使用姿势：新增/修改模块接口时，需要记录其上下游依赖、典型调用方式、适用场景、产出文件和下游消费方式。
4. 设计模式: 涉及到策略模式的设计时，需要记录该设计模式扩展方式、如何使用、适用场景、注意事项等。
5. 高价值经验：代码实现过程中，用户指出的问题、自己发现的代码错误、反复踩坑的问题、环境或工具的稳定约束，都需要被重点记录，防止再次犯错。

## Not Written Rules
不该进入文档的内容
1. 可从代码直接读出的实现细节: 例如变量含义、函数逐句解释、临时重构过程和与代码强绑定且容易漂移的重复描述。
2. **严禁描述单个文件，单个代码作用**，更多的应该描述整个模块的核心概念，作用和功能，**而不是重复一个文件有什么用**
3. 过程噪音: 需求的实现过程，临时草稿，未确认猜测，调试日志等。
4. 当前任务状态的内容: 例如当前任务的进度、状态、依赖关系等。

## Doc Meta Info
文档的元信息
- name: 文档的稳定名称，需要短小、唯一、可作为索引名称。建议使用小写短横线命名，例如 `document-system-contract`。
- description: 文档的简要概述，不超过 100 字。需要说明文档解决的问题，而不是重复标题。
- keywords: 文档的触发短语。当用户需求、任务描述或代码上下文命中这些短语时，Agent 应优先考虑读取该文档。关键词应使用业务短语，例如 `创建文档`、`文档治理`、`防止漂移`，不要只写过宽泛的单词。
- doc_type: 文档类型，用来说明文档属于知识库的哪一类。当前支持 `knowledge | contract | decision | usage | workflow | experience | index`。
- source_path: 文档对应的权威来源路径。可以是源码目录、Agent 文件、Skill 文件、模板文件或规则文件；没有明确来源时填写 `none`。当 `source_path` 指向的内容发生变化时，需要回看该文档是否需要同步更新。

## Doc Path

受治理文档必须使用目录化结构：`docs/<name>/doc.md`。其中 `<name>` 必须和文档 frontmatter 中的 `name` 保持一致；`docs/KNOWLEDGE.md` 中的 Source 链接必须写为 `<name>/doc.md`。不要再创建 `docs/<name>.md` 形式的受治理文档。

# Document Option

**新增/修改任何文档前, 请假设Agent 本身很强，能够理解绝大多数代码和业务，只是容易忽略细节，同时必须阅读 `Written Rules` 和 `Not Written Rules` 后，仔细反问自己以下内容,这段内容真的有必要进入文档系统吗**

## Create A Document

> 新增文档时请确保文档边界和已有文档没有交叉，如果属于同一个描述边界，请优先更新已有文档。

1. 请调用 `create-doc` skill 来完成文件创建、Knowledge 同步和格式校验。

## Change A Document
1. 没有修改 `name`、`description`、`keywords`、`doc_type` 原信息时，只需要修改对应文档即可。
2. 修改了 `name`、`description`、`keywords`、`doc_type` 原信息时，需要同步修改文档所在目录和根目录 `docs/KNOWLEDGE.md` 中 `Source` 对应的原信息。
3. 任何修改完成后，请使用 `create-doc` skill 对文档本身进行验证，同时也需要对 `KNOWLEDGE.md` 文件进行验证。

### Delete a Document
1. 删除文档时，需要删除KNOWLEDGE.md文件的`Source一栏`对应的文档原信息
3. 任何删除完成后，请使用 `create-doc` skill 对KNOWLEDGE.md文件进行验证

**当你完成了文档增删改查，且文档的验证全部通过了。才算完成了文档这边的工作**
